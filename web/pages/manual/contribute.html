Manual: contribute.html Contributor Runtime

Architectural specification, security isolation rules, and operational manual for the CCGSC Contributor Pool runtime.

← Back to Contributor Page

1. Architecture & Sandbox Isolation (WWPP-R29.1, R39.1)

The contributor pool executes untrusted developer WASM and JavaScript workloads inside an opaque sandbox iframe. The sandbox origin (e.g. ccgsc-run.digitalbd.org) is loaded with sandbox="allow-scripts" without allow-same-origin, producing a null origin.

  • Zero Storage / Zero Cookies: LocalStorage, IndexedDB, and cookies are blocked in the opaque realm.
  • Single MessageChannel Handshake: The parent page transfers exactly one MessagePort to the runner via a single bootstrap window.postMessage({type: 'init'}). All subsequent communication is restricted to the port. Window messages are permanently ignored.
  • Byte Transfer: WASM modules are transferred as raw byte buffers and compiled via WebAssembly.compile inside the runner. No network fetch occurs inside the sandbox.

2. Worker Allocation & Device Guards (WWPP-R29.4, WWPP-R30.1, WWPP-R30.2, WWPP-R30.3, WWPP-R31.1, WWPP-R31.2)

Device resource consumption is governed by deterministic hardware rules:

  • Desktop / Laptop Auto Rule: workerCount = max(1, min(4, cores - 1)). Leaves at least 1 core completely free for user responsiveness.
  • Mobile / Phone Auto Rule: 1 compute worker while running on battery; 2 compute workers when actively charging.
  • Two-Tier Worker Model: 1 upkeep worker on the demo origin handles keepalives, lease refreshes, and task scheduling, while 1 to 4 compute workers operate inside the sandbox iframe.
  • Hidden Tab Execution: Background tabs continue computing; the upkeep worker prevents timer suspension, and Web Locks provide multi-tab leader coordination.

3. Security & Cryptographic Envelope (WWPP-R37.1)

Tasks are validated with a mandatory fail-closed verification pipeline before WebAssembly compilation:

  • SHA-256 Hash Verification: Transferred WASM bytes are digested with WebCrypto; the digest must match envelope.artifactSha256 exactly.
  • Ed25519 Envelope Signature: The task envelope is canonicalized to sorted JSON and verified against the server's Ed25519 public key.
  • Lease Bounds: Tasks with expired leases (leaseExp < now) are rejected immediately.
