# F11 — Production P2P per G-F11-1/2 (design and wiring)

2026-11-25. Base 063bfac5. Owner grill section 16 is the truth: G-F11-1 (same-app
only peers, SHA-256 checked, HTTP fallback) and G-F11-2 (admin modes on the pools
admin panel: self-hosted STUN-only, LAN-only host candidates; no public STUN, no
TURN). Supersedes the D-W10-14 optional-TURN decision; `rules.turnAllowed` is now
a fail-closed stub and is removed by the next cleanup.

## 1. What is on by default

Nothing. The admin panel rows `tp.p2p.mode` / `pp.p2p.mode` are enum
`stun/lan/off` with default `off` ("default per admin": only a pools admin
decision turns a pool on; a job cannot - `internal/pool` `applyOptions` still
refuses `options.p2p` with ErrUnsupported). The contributor consent gate
(G-F10-4) is the second key: `createProductionP2p` runs only when the page's
`enabled()` (admin mode on AND consent) is true.

## 2. Layers

- `web/pages/js/platform/p2p/rules.js`: pure rules — modes, same-app check,
  stun URL validation with a public-provider denylist, iceServers sanitizer
  (drops turn:, strips credentials: no secrets in the browser).
- `.../p2p/signaling.js`: pools-core signaling client (register/leave/
  discover/signal send+poll). Re-checks every app binding and every envelope
  cap client-side; discovery payload carries only peerId/appId/mode.
- `.../p2p/production.js`: the conductor. cache (provenance) -> same-app peer
  (mode-derived RTC configuration; `lan` = empty iceServers, host candidates
  only) -> one hash-verified HTTP fallback. Peer bytes are NEVER admitted to
  the provenance cache (`putVerified` stays server-ingest only). Serving is
  gated by consent + battery + claims pause + the rolling 64 MiB/min budget.
- `.../p2p/transport.js`: the reviewed transport-only draft, byte-identical
  (its protocol, caps and tests are kept).
- `internal/p2p`: signaling hub over PostgreSQL (`p2p_peers`, `p2p_messages`,
  `p2p_config`). Multi-server safety: the same-app rule of G-F11-1 is enforced
  by the `INSERT ... SELECT ... WHERE EXISTS` statement in `pg.go`, so two
  instances cannot race a cross-app relay past a process-local check.
- `internal/api/p2p.go`: the HTTP surface under both pool prefixes (register,
  leave, peers, signal GET/POST, config GET/PUT-admin).

## 3. Admin surface (pools admin panel)

`tp.p2p.mode` / `pp.p2p.mode` (enum stun/lan/off, admin-only, default off) plus
`GET/PUT {prefix}/p2p/config` for the server-side configuration. The STUN URLs
of mode `stun` live ONLY in pools server configuration (p2p_config table) —
validated as `stun:`/`stuns:` with host denylist (public providers refused);
TURN URLs are refused in every mode. The browser receives only the sanitized
`iceServers` payload, which cannot express credentials.

## 4. New choices made here (approved in spirit; flagged per the WO rule)

- Signaling transport: HTTPS request/poll with a cursor (not WebSocket). Reason:
  3-5 short envelopes per handshake, reuses the existing REST+SSE-style surface,
  no new connection lifecycle; the wire caps (rules.js SIGNAL_* constants) are
  enforced on both ends. WSS can replace the poll later without protocol
  changes (G-F10-3 keeps HTTPS+WSS as the protocols).
- Peer discovery piggybacks on registration presence (`p2p_peers`, TTL 90 s =
  rules.js PEER_TTL_MS) instead of a separate heartbeat; polls refresh presence.
- Relay queue: PostgreSQL with per-message TTL 60 s, max 32 queued per peer,
  drained by cursor and deleted on delivery. Redis pub/sub is NOT required for
  correctness; it can front the poll path later for latency.
- Peer id: random session id from the tab (`crypto.randomUUID`); the server
  binds peer id <-> lease and refuses a live peer id hijack by another lease.
- Non-trickle ICE: offers/answers carry the full SDP (gathering bounded at
  2.5 s); no `candidate` envelopes are sent by this client.
- Serving window: a tab serves only artifacts its transport fetched over HTTP
  in the last 60 s (transport's bounded cache); a miss declines and the
  requester falls back to HTTP. The provenance cache remains the page-level
  module cache.

## 5. Qualification and deploy notes (NO deploy by the agent)

- `lan` mode needs no infra. `stun` mode needs the owner's coturn STUN listener
  on the VPS at deploy (STUN only; no TURN relay config).
- The server assembly must call `SetP2PAuthenticator(peerAuth, adminAuth)`
  (lease-token verifier from F10 + admin check) and mount `P2PMux(hub)` with a
  hub over `p2p.NewPGStore(db)` + `p2p.NewPGConfigStore(db)`. Both seams fail
  closed (503/401) when not wired.
- `p2p.PGStore.EnsureSchema` creates the three tables idempotently; adopt them
  into the migration harness of the deployment at deploy time.
- Results and receipts never traverse P2P (envelopes cannot express them);
  module artifacts only, SHA-256 verified on every hop, HTTP fallback once.
